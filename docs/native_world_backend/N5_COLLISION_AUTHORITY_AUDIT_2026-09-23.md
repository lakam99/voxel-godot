Status: preparation only. Production collision has **not** switched.

The production `VoxelTerrainRuntime` still sets `VoxelTerrain.generate_collisions = true`, configures its terrain collision layer, and attaches viewers with `requires_collisions = true`. Its chunk receipts use `is_area_meshed()` and physics probes. The installed Voxel Tools binary therefore owns current terrain colliders and broad viewer demand. The N3 manual-data publisher also leaves Voxel Tools collision enabled in its headed mechanism fixture. Neither a native data-block insertion nor a mesh-enter signal proves a current physical collider.

The N2 fixture demonstrates the alternative public-API configuration: `generate_collisions = false`, rendering viewer `requires_collisions = false`, and one project-owned `StaticBody3D` receiving native shapes. This is a fixture, not a production switch. The plugin installation contains a GDExtension binary and editor assets, not source or a public API for intercepting its internal collision scheduling. A production cutover must disable both terrain collision generation and collision-requiring viewer demand, then replace every startup, movement, navigation and edit readiness consumer atomically. It also needs a complete native terrain plus feature shape artifact, including seams, vertical spans and durable edits; the current N2 fixture artifact is bounded to its test region.

`NativeTerrainCollisionOwner.physical_receipt()` now exposes a fail-closed, revision-bound read of that fixture mechanism. It returns the acknowledged physics frame and source/artifact provenance. Replacement of existing shapes requires a caller-supplied occupancy guard, checked before installation and at each acknowledgement frame; rejection leaves the old physical shapes installed. The fixture proves rejection with a deliberately blocking guard and successful replacement with a clear guard. It does **not** prove actor-safe gameplay: the fixture does not supply a live actor occupancy/swept-volume query or suspend actor entry through the switch, and no production consumer calls this owner yet.

## Required live actor guard before production replacement

The caller-supplied guard currently returns a boolean. A production implementation must bind it to an exact affected tile set and revision, enumerate live player/NPC/hostile bodies and their actual collision shapes, and test both present occupancy and each admitted movement sweep against old and candidate geometry. It must hold a region admission barrier from the last guard query through the physics switch and release it only after the new physical revision is acknowledged or the old one is restored. A body entering while the barrier is held must wait or receive an explicit retry; it cannot be silently admitted on a stale receipt. This requires coordination with the established movement admission contracts without modifying protected route semantics. The current N2 fixture has no such live registry or barrier, so its clear guard is deliberately insufficient as actor-safety evidence.

`NativeCollisionActorGuard.inspect()` is a conservative precursor. It checks a supplied set of live `CharacterBody3D` collision shapes against a bounded AABB spanning each body's current and velocity-forecast bounds. It fails closed for invalid regions, missing shapes and invalid actor entries. The focused headed N2 fixture exercises a real body in the region, a body whose forecast enters the region, and a clear body. Command: `node tools/run-n2-native-world-vertical-slice.mjs`; report: `artifacts/native-world-backend/n2-vertical-slice-2026-09-23T14-11-01-045Z-e82309a9/receipt.json`. Fixture validation is `valid: true` and actor guard evidence is `ok: true`; outer release status remains failed because the ignored installed binaries/manifests were copied into the isolated worktree for this fixture, not freshly built/bound here. The helper cannot guarantee completeness of the actor registry, account for acceleration/instantaneous movement, or prevent entry between guard and physics acknowledgement. Do not wire it as production safety without the admission barrier and current exact collision artifact.

`NativeCollisionAdmissionBarrier` is now a composed service that scans a declared scene root for all `CharacterBody3D` actors at begin and every clearance, holds an exact replacement identity and bounds, refuses admitted motion into the region, and fails closed at 8,192 scene nodes or 512 actors. Its `release` requires the collision owner to return a current matching `physical_receipt` with a physics frame; rejected/cancelled replacements use a separate `abort` path after the owner has stopped installing. `NativeTerrainCollisionOwner.replace` requires this barrier for replacement of installed shapes and rechecks census/clearance at every acknowledgement frame. Headed fixture command: `node tools/run-n2-native-world-vertical-slice.mjs`; report: `artifacts/native-world-backend/n2-vertical-slice-2026-09-23T14-18-59-111Z-847e283a/receipt.json`. This is a production-facing interface, **not** production actor-safe cutover. ## Incremental actor census slice

The isolated N5 barrier now starts a pending census and advances at most 256 scene nodes or 3 ms per call; its tree signals maintain the actor set after the initial walk, so clearance no longer rescans the entire scene. `begin` and `advance_census` return pending until the walk finishes, and collision installation/release stays held. Movement by a live, complete-shape actor that conclusively misses the affected bounds is allowed during the pending walk; a swept entry is denied. A moving static body that acquires its group while already tree-resident must call `register_moving_actor`.
