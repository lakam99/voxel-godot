# N5 collision authority audit and first physical receipt slice

Status: preparation only. Production collision has **not** switched.

The production `VoxelTerrainRuntime` still sets `VoxelTerrain.generate_collisions = true`, configures its terrain collision layer, and attaches viewers with `requires_collisions = true`. Its chunk receipts use `is_area_meshed()` and physics probes. The installed Voxel Tools binary therefore owns current terrain colliders and broad viewer demand. The N3 manual-data publisher also leaves Voxel Tools collision enabled in its headed mechanism fixture. Neither a native data-block insertion nor a mesh-enter signal proves a current physical collider.

The N2 fixture demonstrates the alternative public-API configuration: `generate_collisions = false`, rendering viewer `requires_collisions = false`, and one project-owned `StaticBody3D` receiving native shapes. This is a fixture, not a production switch. The plugin installation contains a GDExtension binary and editor assets, not source or a public API for intercepting its internal collision scheduling. A production cutover must disable both terrain collision generation and collision-requiring viewer demand, then replace every startup, movement, navigation and edit readiness consumer atomically. It also needs a complete native terrain plus feature shape artifact, including seams, vertical spans and durable edits; the current N2 fixture artifact is bounded to its test region.

`NativeTerrainCollisionOwner.physical_receipt()` now exposes a fail-closed, revision-bound read of that fixture mechanism. It reports ready only after the real physics probe has acknowledged the currently installed shape set, while the owner is available, no replacement is in progress, the shapes remain live and enabled, and authority still matches the exact `(ownerGeneration, sourceRevision, cancellationEpoch)` identity. It returns the acknowledged physics frame and source/artifact provenance. Replacement of existing shapes requires a caller-supplied occupancy guard, checked before installation and at each acknowledgement frame; rejection leaves the old physical shapes installed. The fixture proves rejection with a deliberately blocking guard and successful replacement with a clear guard. It does **not** prove actor-safe gameplay: the fixture does not supply a live actor occupancy/swept-volume query or suspend actor entry through the switch, and no production consumer calls this owner yet.

Focused headed command: `node tools/run-n2-native-world-vertical-slice.mjs`. Latest report: `artifacts/native-world-backend/n2-vertical-slice-2026-09-23T14-00-17-716Z-d22f3efb/receipt.json`. The fixture itself reports `passed: true`; the added assertions checked the new receipt against rejected stale installs, a successful baseline, a same-shape new epoch, an edited install, and a blocked replacement. The outer N2 receipt is `failed` because its complete release/build/clean-worktree gate is not met in this shared dirty worktree; its validation also reports `fixture_resource_lifecycle_invalid` (the fixture records three admitted requests while the runner validator still expects two). This run is mechanism evidence only. It does not prove normal gameplay, actor-safe swap, bounded production streaming or Gate 5.

Next N5 cutover evidence needs a native full-source collision artifact, explicit per-region transaction and affected-set identity, occupancy guard across the physics boundary, retained old valid shapes until safe switch, cancellation/retry for edits and reversals, and a headed actor traversal through startup, edits and revisit. Only then can the Voxel Tools collision owner be disabled without leaving a physical gap or duplicate authority.
