The N3 manual-data publisher also leaves Voxel Tools collision enabled in its headed mechanism fixture. This is a fixture, not a production switch. The plugin installation contains a GDExtension binary and editor assets, not source or a public API for intercepting its internal collision scheduling. `NativeTerrainCollisionOwner.physical_receipt()` now exposes a fail-closed, revision-bound read of that fixture mechanism. It returns the acknowledged physics frame and source/artifact provenance. Replacement of existing shapes requires a caller-supplied occupancy guard, checked before installation and at each acknowledgement frame; rejection leaves the old physical shapes installed. The fixture proves rejection with a deliberately blocking guard and successful replacement with a clear guard. It does **not** prove actor-safe gameplay: the fixture does not supply a live actor occupancy/swept-volume query or suspend actor entry through the switch, and no production consumer calls this owner yet.

## Required live actor guard before production replacement

The caller-supplied guard currently returns a boolean. A production implementation must bind it to an exact affected tile set and revision, enumerate live player/NPC/hostile bodies and their actual collision shapes, and test both present occupancy and each admitted movement sweep against old and candidate geometry. It must hold a region admission barrier from the last guard query through the physics switch and release it only after the new physical revision is acknowledged or the old one is restored. A body entering while the barrier is held must wait or receive an explicit retry; it cannot be silently admitted on a stale receipt. This requires coordination with the established movement admission contracts without modifying protected route semantics. The current N2 fixture has no such live registry or barrier, so its clear guard is deliberately insufficient as actor-safety evidence.

`NativeCollisionActorGuard.inspect()` is a conservative precursor. It checks a supplied set of live `CharacterBody3D` collision shapes against a bounded AABB spanning each body's current and velocity-forecast bounds. It fails closed for invalid regions, missing shapes and invalid actor entries. The focused headed N2 fixture exercises a real body in the region, a body whose forecast enters the region, and a clear body. Command: `node tools/run-n2-native-world-vertical-slice.mjs`; report: `artifacts/native-world-backend/n2-vertical-slice-2026-09-23T14-11-01-045Z-e82309a9/receipt.json`. Fixture validation is `valid: true` and actor guard evidence is `ok: true`; outer release status remains failed because the ignored installed binaries/manifests were copied into the isolated worktree for this fixture, not freshly built/bound here. The helper cannot guarantee completeness of the actor registry, account for acceleration/instantaneous movement, or prevent entry between guard and physics acknowledgement. Do not wire it as production safety without the admission barrier and current exact collision artifact.

Next N5 cutover evidence needs a native full-source collision artifact, explicit per-region transaction and affected-set identity, occupancy guard across the physics boundary, retained old valid shapes until safe switch, cancellation/retry for edits and reversals, and a headed actor traversal through startup, edits and revisit. Only then can the Voxel Tools collision owner be disabled without leaving a physical gap or duplicate authority.
