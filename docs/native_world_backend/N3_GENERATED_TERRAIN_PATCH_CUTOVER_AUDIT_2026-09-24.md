# N3 Generated Terrain Patch Cutover Audit

Date: 2026-09-24

Status: audit/design checkpoint only. This document records the production
authority and call graph, the required native-source composition, a staged
cutover, and the deletion gates. It does **not** claim that
`NativeGeneratedTerrainPatch` is integrated, that production authority has
changed, or that any contract, Godot, headed, save, collision, navigation, or
performance test has passed. The audit itself made no production code changes
and ran no tests.

The production tree audited here is the script/VoxelTerrain authority at
commit `f58685c1dcdf`. The pure-core `NativeGeneratedTerrainPatch` candidate is
referenced from commit `c0edd3c`; it is not present or active in this production
tree. Its source-identity correction is a prerequisite to integration, not
evidence of integration.

## Decision

`NativeGeneratedTerrainPatch` is the right kind of authority for terrain
generated by a structure recipe, but it must replace, not populate,
`TerrainVolumeService.edited_cells`.

The required effective-terrain precedence is:

```text
durable explicit terrain override, including explicit AIR
  > generated terrain patch
  > natural / town / admitted site terrain
```

Generated patches are deterministic generated source. They are not edited
cells, are not durable save deltas, and must bind the exact upstream generated
definition/source manifest from which they were derived. Query, voxel data,
mesh, collision, readiness, save export, prop exclusion, and downstream
navigation publication must refer to the same pinned effective source.

The current path cannot be retained as a compatibility writer. Expanding a
native patch back into `edited_cells` would retain the precedence defect and
create a second generated-terrain authority.

## Production authority and call graph

### Generic town, home, standalone, and tutorial footprints

The production flow is:

```text
world seed / town region / standalone candidate / scenario layout
  -> StructureSystem scheduling and builders
  -> StructureSystem.reserve_structure_terrain_footprint
  -> three WorldGenerationSystem.apply_box_edit calls
  -> TerrainVolumeService.edited_cells
  -> copied startup edits or live VoxelTerrain paste
  -> terrain mesh and VoxelTerrain collision
  -> collision publication receipt
  -> existing navigation publication consumer
```

The concrete callers are:

- Town discovery and build scheduling in
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L532-L554), with
  deterministic home construction in
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1306-L1347).
- Generic buildings call the footprint writer before scene blocks are placed in
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1796-L1821).
- Ruin, camp, mine, and shrine builders call it at
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1895-L1900),
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1918-L1924),
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1964-L1969), and
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L2007-L2013).
- The starter shelter independently uses the same generic method in
  [`TutorialSceneBuilder.gd`](../../scripts/TutorialSceneBuilder.gd#L92-L110).
- Deferred generation serializes a `terrain_footprint` operation and later
  re-enters the writer in
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L827-L862) and
  [`StructureSystem.gd`](../../scripts/StructureSystem.gd#L984-L997).

`reserve_structure_terrain_footprint` emits three inclusive boxes in
[`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1003-L1064):

1. Foundation fill: X/Z `base - 1` through `base + width/depth`, and Y
   `floorY - 3` through `floorY - 1`.
2. Floor cap: the same X/Z box at `floorY`.
3. Interior clearance AIR, when the interior is large enough: inner X/Z and Y
   `floorY + 1` through `floorY + clearance`.

All three are ordinary `apply_box_edit` calls. Their metadata contains
`saveDelta:false`, but that flag filters save serialization; it does not create
a generated-source layer.

The parallel metadata representation is
`terrain_footprint_records`, declared at
[`StructureSystem.gd`](../../scripts/StructureSystem.gd#L44) and written by
[`record_structure_terrain_footprint`](../../scripts/StructureSystem.gd#L1066-L1090).
Its identity is only:

```text
source:baseX,baseZ:widthxdepth:floorY
```

It is not bound to an upstream manifest digest, generic homes share the source
name `town_home`, and its vertical `maxCell` stops at the floor cap rather than
including interior-clearance operations. It is therefore neither a complete
physical manifest nor a sufficient source receipt.

### Current TerrainVolumeService composition

The current cell lookup order is:

```text
scene_block_cells
  > edited_cells
  > loaded/generated section state
  > generated natural/site state
```

This is implemented by
[`TerrainVolumeService.get_cell_state`](../../scripts/TerrainVolumeService.gd#L1005-L1015).

[`TerrainVolumeService.apply_box_edit`](../../scripts/TerrainVolumeService.gd#L2072-L2123)
unconditionally replaces any previous `edited_cells` entry and then calls
`_update_durable_delta_cell` for the replacement. Because structure footprint
metadata says `saveDelta:false`,
[`_update_durable_delta_cell`](../../scripts/TerrainVolumeService.gd#L2259-L2275)
erases the durable bucket record at that cell.

[`clear_cell_state`](../../scripts/TerrainVolumeService.gd#L1078-L1105) removes
the single edited entry and restores `generated_cell_state`; there is no lower
generated-patch layer to reveal.

The observable precedence is therefore write order, not source semantics:

1. A regenerated footprint written after a saved/player edit wins and erases
   that edit from the next `terrainVolume` export.
2. An explicit edit written after a footprint wins, but clearing it reveals
   natural/site terrain instead of the footprint.
3. Structure regeneration timing can change effective terrain for the same seed
   and durable save.

There is also a generated-source dependency on durable edits.
[`StructureSystem.terrain_surface_sample_at_cell`](../../scripts/StructureSystem.gd#L900-L955)
uses edit-aware volume projection when a column contains a
surface-projection-affecting edit. A standalone feature first discovered after
a player edit can therefore derive placement or material context from that
edit. A generated patch manifest must instead be planned from a pinned lower
natural/town/site source, independent of durable deltas and discovery order.

### Save, Continue, and regeneration

The save path records `terrainVolume` in
[`MainSaveState.create_save_snapshot`](../../scripts/MainSaveState.gd#L106-L140).
Only player-placed scene blocks are retained by
[`snapshot_player_blocks`](../../scripts/MainSaveState.gd#L426-L451).
[`TerrainVolumeService.save_all_section_deltas`](../../scripts/TerrainVolumeService.gd#L2243-L2257)
exports only durable buckets.

Continue restores durable terrain at
[`MainSaveState.apply_save_snapshot`](../../scripts/MainSaveState.gd#L167-L209)
and
[`restore_terrain_volume`](../../scripts/MainSaveState.gd#L385-L393).
Main then reinitializes terrain authority before tutorial reconstruction at
[`MainCore.gd`](../../scripts/MainCore.gd#L519-L533) and during runtime Continue
at [`MainCore.gd`](../../scripts/MainCore.gd#L2939-L2965).
[`TutorialSystem.complete_restore_world_staged`](../../scripts/TutorialSystem.gd#L168-L222)
subsequently rebuilds required town and shelter content.

Thus current Continue loads a durable AIR edit and can then regenerate a
structure footprint over it. Because the structure write also removes the
durable bucket entry, a subsequent save can permanently lose the user's edit.
Filtering the generated write out of serialization does not protect the
pre-existing durable record.

The target load order is different:

```text
freeze deterministic generated source manifests
  -> admit generated terrain patches
  -> import durable save-v2 deltas over those patches
  -> pin one effective source
  -> publish query/mesh/collision/readiness/save ownership together
```

Actual scene structure publication may follow, but it must wait for the patch's
physical publication receipt. It must not create the terrain patch after the
effective source is already active.

### Startup and live meshing/collision

The script startup path copies every mesh-affecting `edited_cells` entry,
including non-durable footprints, into `initial_terrain_edits` in
[`VoxelWorldGenerationContext.gd`](../../scripts/terrain/VoxelWorldGenerationContext.gd#L50-L66).
[`VoxelTerrainGenerator.gd`](../../scripts/terrain/VoxelTerrainGenerator.gd#L34-L70)
substitutes those saved/edit states for generated density and material.

The live path scans the same mutable dictionary in
[`VoxelTerrainRuntime.collect_volume_edit_changes`](../../scripts/terrain/VoxelTerrainRuntime.gd#L1822-L1848)
and pastes SDF/material data into VoxelTerrain in
[`VoxelTerrainRuntime.gd`](../../scripts/terrain/VoxelTerrainRuntime.gd#L1901-L1958).
Collision publication waits for pending edit sections and physics probes in
[`VoxelTerrainRuntime.gd`](../../scripts/terrain/VoxelTerrainRuntime.gd#L2052-L2163).

Structure edits affect the terrain mesh but are explicitly excluded from
surface projection by a source-name test in
[`TerrainVolumeService.gd`](../../scripts/TerrainVolumeService.gd#L3128-L3139).
The collision proof's `passed` result requires a meshed area and the expected
hit count, but not `heightfieldComparisonPassed`, in
[`VoxelTerrainRuntime.gd`](../../scripts/terrain/VoxelTerrainRuntime.gd#L2147-L2156).
That allows projection and physical structure-patch surfaces to disagree.

Navigation is a consumer, not an owner to modify in this cutover.
[`GeneratedWorldNavigationAdapter`](../../scripts/npc_ai/navigation/GeneratedWorldNavigationAdapter.gd#L343-L350)
already asks Main for terrain publication readiness, and its tile snapshot
stays pending until that physical source is ready at
[`GeneratedWorldNavigationAdapter.gd`](../../scripts/npc_ai/navigation/GeneratedWorldNavigationAdapter.gd#L380-L400).
The patch identity must enter the existing terrain physical receipt. No new
navigation topology or routing authority is proposed.

### Destruction

Generated structure block destruction does not create a durable generated
feature tombstone:

- Block removal clears/freezes the scene-block path in
  [`MainPropFactory.gd`](../../scripts/MainPropFactory.gd#L150-L178).
- Only props add entries to `removed_props` at
  [`MainPropFactory.gd`](../../scripts/MainPropFactory.gd#L179-L220).
- Generated blocks are omitted from
  [`snapshot_player_blocks`](../../scripts/MainSaveState.gd#L426-L451).
- Removing a scene block reveals its replaced terrain or generated baseline in
  [`MainChunkTerrain.gd`](../../scripts/MainChunkTerrain.gd#L336-L364).

Generated building blocks can therefore return after Continue while their
terrain footprint remains. Initial patch operations must use
`permanent_site_shaping` for current-behaviour parity. Do not enable
`follows_feature_tombstone` until N4 provides a typed, stable, durable
generated-feature tombstone authority. `removedProps` is not a generic
structure tombstone namespace.

## Citadel and exact building geometry are separate

Citadel terrain grounding does not currently call
`reserve_structure_terrain_footprint`. Its source path is:

```text
BuildingSiteManifestBuilder sourceSignature
  -> BuildingTerrainProfile
  -> CitadelTerrainAdmission
  -> natural/site surface shaping in WorldGenerationSystem
```

[`BuildingSiteManifestBuilder`](../../scripts/buildings/BuildingSiteManifestBuilder.gd#L25-L33)
canonically hashes original blueprint/furnishing source fields and returns the
`sourceSignature` with the immutable manifest at
[`BuildingSiteManifestBuilder.gd`](../../scripts/buildings/BuildingSiteManifestBuilder.gd#L118-L141).

[`BuildingTerrainProfile`](../../scripts/world/BuildingTerrainProfile.gd#L4-L6)
is explicitly a pure generated-terrain input, not a terrain edit, mesh, or
collider, and retains the manifest signature in
[`BuildingTerrainProfile.gd`](../../scripts/world/BuildingTerrainProfile.gd#L14-L54).
[`CitadelTerrainAdmission`](../../scripts/world/CitadelTerrainAdmission.gd#L353-L376)
verifies that profile and manifest signatures match. Town shaping has priority,
and admitted site profiles shape the lower generated surface in
[`WorldGenerationSystem.gd`](../../scripts/WorldGenerationSystem.gd#L1051-L1077).

Citadel foundation, paving, ramp, floor, threshold, and support parts are exact
building-feature geometry with separate scene/collision publication. For
example,
[`CivicCourtyardSupport.gd`](../../scripts/buildings/CivicCourtyardSupport.gd#L8-L19)
validates continuous colliding foundation geometry, and
[`CitadelUrbanPocComposer.gd`](../../scripts/buildings/CitadelUrbanPocComposer.gd)
authors the exact parts.

The generic patch cutover must not voxelize those exact feature shapes or add
equivalent terrain patches on top of `BuildingTerrainProfile`. Either action
would create duplicate geometry/collision authority. In this tranche:

- keep town/site shaping below generated-patch precedence;
- keep exact citadel building parts as declared feature geometry;
- apply the generated patch only to the generic foundation/floor/clearance boxes
  currently emitted by `reserve_structure_terrain_footprint`.

If site profiles are migrated later, atomically replace their natural/site
sampling with the new representation and delete the old sampling path. Never
run both interpretations for the same source manifest.

## Pure-core candidate identity audit

The candidate at commit `c0edd3c` correctly defines:

- source-layer order in
  `native/world_backend/core/native_generated_terrain_patch.hpp:16-24`;
- foundation, floor-cap, and interior-clearance roles plus lifecycle in
  `:26-35`;
- a generated cell template deliberately lacking edit/save/persistence policy
  in `:52-65`;
- a complete-region manifest and canonical patch content digest in `:151-185`;
- an immutable page-local crop and page projection digest in `:216-266`.

Two different identities are required and must not be conflated:

1. **Canonical patch digest.** This hashes the admitted patch descriptor and
   compact operations. It proves exactly which patch bytes were admitted.
2. **Exact upstream generated-definition/source-manifest digest.** This proves
   which town/home/standalone/scenario/building definition caused those
   operations.

The audited candidate descriptor at
`c0edd3c:native/world_backend/core/native_generated_terrain_patch.hpp:151-160`
contains world physical identity, `region_id`, a producer revision, an integer
`feature_source_revision`, and operations. It does not contain the required
upstream source-manifest digest. A revision integer and the derived patch digest
cannot prove the patch was derived from the correct source definition.

Before integration, the corrected core value must require:

- a nonzero canonical `source_manifest_digest` on each complete region
  manifest;
- stable per-owner generated-definition identity, either retained directly or
  checked against the N4 footprint catalog;
- both identities in canonical serialization, page projection, source pins,
  asynchronous results, and physical receipts.

The existing N4 catalog already models per-feature
`generated_definition_digest` at
[`native_generated_feature_footprint_catalog.hpp`](../../native/world_backend/core/native_generated_feature_footprint_catalog.hpp#L36-L48)
and binds the catalog to a source digest/revision at
[`native_generated_feature_footprint_catalog.hpp`](../../native/world_backend/core/native_generated_feature_footprint_catalog.hpp#L68-L97).
Patch and footprint catalogs must be admitted together or cross-validated by
owner ID and generated-definition digest. Two independently accepted catalogs
would be a second source authority.

## Target source composition

### Stable producers and operation order

A generic structure source-planning stage must produce complete region
manifests before scene publication. It must reuse the real deterministic town,
standalone, and scenario inputs, not copy their recipes into a second generator.

Owner IDs must come from the actual stable feature manifest, for example:

```text
town:<town-stable-id>:home:<home-stable-id>
standalone:<region-id>:<candidate-stable-id>
scenario-structure:<scenario-manifest-id>:<structure-stable-id>
```

Generic strings such as `town_home` are presentation/category fields, not
physical owner identity.

For each current footprint, emit the existing geometry as compact operations:

- ordinal 0: foundation fill;
- ordinal 1: floor cap;
- ordinal 2: interior clearance, if present.

Cross-feature overlap order must be canonical source-manifest order, never
camera approach, queue timing, mutable dictionary order, or worker completion.
Biome/material values must derive from a pinned lower natural/town/site source.

### Effective native resolution

All native terrain query channels must resolve:

```text
durable typed cell, including explicit AIR
  > generated patch page snapshot
  > natural/town/site generated cell
```

The patch insertion points include:

- cell-state resolution in
  [`native_effective_terrain_source.cpp`](../../native/world_backend/core/native_effective_terrain_source.cpp#L678-L733);
- lattice numeric resolution in
  [`native_effective_terrain_source.cpp`](../../native/world_backend/core/native_effective_terrain_source.cpp#L597-L619);
- batch sparse/result handling in
  [`native_effective_terrain_batch.cpp`](../../native/world_backend/core/native_effective_terrain_batch.cpp#L196-L200)
  and
  [`native_effective_terrain_batch.cpp`](../../native/world_backend/core/native_effective_terrain_batch.cpp#L301-L328).

A resolved patch cell reports `generated=true`, `edited=false` and never enters
save-v2 `terrainVolume` export.

Scene-block overlays remain an exact-feature/occupancy namespace. Gameplay
occupancy may compose scene blocks above effective terrain, but generated scene
blocks must not become terrain patches, and patches must not duplicate exact
building collision.

## Minimal adapter and source transaction

Do not expose a per-cell patch write API. Existing effective-page pins, terrain
batch reads, voxel-block production, and collision artifact production should
consume patch-aware pins internally.

The minimal new Godot/native boundary is:

1. **Bounded patch import/replacement lifecycle integrated with the retained
   native source transaction.** Begin with world identity, source-manifest
   digest, producer/feature revisions, complete-region declarations, counts,
   and hard limits; append compact manifests in bounded batches; finalize and
   validate privately; expose status/cancel/drain; commit only with the whole
   source candidate.
2. **Patch-aware page pin and receipt.** Expose base world identity, exact
   upstream source-manifest digest, canonical patch digest, patch registry
   revision, page projection digest, durable delta revision, local typed-delta
   projection digest, affected sections/halo, owner generation, and source
   epoch.
3. **Complete-region replacement transaction for later streaming discovery.**
   Stage the new region manifest and all affected physical artifacts without
   changing the active page. There must be no public adapter that expands the
   patch into script edits.

[`NativeWorldSourceRequest`](../../scripts/terrain/NativeWorldSourceRequest.gd#L53-L64)
currently contains seed, generator revisions/constants, site policy, and town
overrides, but not generated terrain patch manifests.
[`NativeTerrainLoadTransaction`](../../scripts/terrain/NativeTerrainLoadTransaction.gd#L40-L118)
currently borrows only `terrainVolume`, strips it from the small descriptor,
and stages native import. The generated source manifest and an immutable owner
lease belong in that same retained transaction.

[`NativeTerrainCellSource`](../../scripts/terrain/NativeTerrainCellSource.gd#L34-L40)
currently observes global delta and shaping revisions and checks them around
page reads at
[`NativeTerrainCellSource.gd`](../../scripts/terrain/NativeTerrainCellSource.gd#L68-L95).
It must also compare the patch-aware page pin physical identity/projection
digest. A global registry revision may detect a read race, but it must not make
an unrelated distant patch part of a local artifact's cache key.

## Identity, revision, and invalidation rules

Use separate identities with separate responsibilities:

- `terrainDeltaRevision`: changes only for durable explicit terrain edits.
- `generatedPatchRegistryRevision`: advances when a complete-region patch
  catalog is replaced or admitted.
- `sourceManifestDigest`: exact upstream generated definition.
- `patchManifestDigest`: canonical compact patch operations.
- `pageProjectionDigest`: only admitted operations/tombstones intersecting the
  owned page bounds and required mesh halo.
- `pagePhysicalIdentity`: natural/site shaping identity + page patch projection
  digest + local durable-delta projection digest.
- owner generation/source epoch: installation ownership, not content
  equivalence.

A distant patch update may advance the global registry revision but must not
change an unrelated page's physical identity. The existing `WorldSourcePin`
already combines local shaping and typed-delta projection identity in
[`world_source.cpp`](../../native/world_backend/core/world_source.cpp#L300-L376);
the patch page projection must join that same physical pin.

Affected pages invalidate:

- native voxel/SDF blocks and required mesh halo;
- render mesh and resident collision receipts;
- surface projection, top-surface, skylight/fluid-derived work for affected
  cells;
- structure physical readiness;
- tree and prop exclusion artifacts derived from the same feature source;
- downstream navigation publication receipts through the existing terrain
  collision readiness contract.

The mutable tree/prop exclusions currently read footprint records in
[`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1139-L1192) and
[`StructureSystem.gd`](../../scripts/StructureSystem.gd#L1281-L1289). They must
consume an immutable active patch/N4 feature projection with matching owner
definition digest. Keeping `terrain_footprint_records` beside that source would
retain a second exclusion authority.

## Four-stage evidence plan

No stage below has been executed by this audit.

### Stage 1: real-producer operation shadow

Capture a shadow descriptor at the existing
`reserve_structure_terrain_footprint` boundary while leaving current
`apply_box_edit` authoritative. Exercise the real deterministic builders for
town homes, cabins, ruins, camps, mines, shrines, and generic scenario shelter
construction. Do not call a synthetic helper in place of those producers.

Compare:

- all three inclusive operation boxes;
- role, material, biome, density, light, and lifecycle;
- floor conversion, section projection, negative coordinates, and hard bounds;
- stable owner ID and exact upstream generated-definition digest;
- canonical overlap order and duplicate/idempotent admission;
- affected sections and mesh halo.

Citadel `BuildingTerrainProfile` and exact citadel building geometry are a
separate lane. Do not fabricate generic patch operations for them merely to
make a fixture comprehensive.

### Stage 2: effective state and precedence migration

Use two explicit lanes:

1. **Legacy parity without durable overlap.** Patch resolution must match the
   current post-`apply_box_edit` effective state for material, biome, solidity,
   density, fluid, light, and geometry.
2. **Target precedence with durable overlap.** Apply durable solid and explicit
   AIR states before and after structure regeneration. Prove that they survive
   generated patch admission, explicit clear semantics, export/import, and
   Continue. Current divergence is the documented defect and must not be copied
   into the target.

Also prove that prior durable edits do not alter generated patch source
planning. The same seed/source manifest must produce the same patch digest
regardless of discovery/query order.

### Stage 3: physical parity

From identical real producer inputs, compare:

- patch-aware native voxel-block SDF/material bytes with the current production
  source bytes;
- mesh bounds, seams, and empty/nonempty artifact semantics;
- live Godot collision surfaces and source-bound replacement receipts;
- New Game and Continue import/export, proving only durable deltas persist;
- local invalidation under patch and durable-delta changes;
- source/physical receipt rejection for stale owner generations.

Metadata-only footprint checks, service booleans, or mocked collision do not
establish physical acceptance.

### Stage 4: headed acceptance

After core, adapter, source, and physical gates pass, run and inspect:

- real main-menu to New Game;
- Continue with durable explicit AIR inside a generated foundation;
- distant structure discovery, retirement, and revisit;
- generated structure block destruction/reload under the current
  permanent-site-shaping lifecycle;
- town/tutorial visual and real collision evidence;
- normal runtime traversal/performance observation;
- the applicable existing navigation/pathfinding regressions and headed runs,
  without modifying the protected route stack.

Report exact commands, seeds, reports, screenshots/traces, physical receipts,
worst frame, and what each run does and does not prove.

## Atomic activation and rollback

The existing N3 ledger requires source, physical readiness, and save ownership
to switch together; see
[`N3_TERRAIN_CELL_SOURCE_CUTOVER_LEDGER_2026-09-23.md`](N3_TERRAIN_CELL_SOURCE_CUTOVER_LEDGER_2026-09-23.md#production-cutover-checkpoint-ordered-owners-and-atomic-staging).

For initial New Game/Continue:

1. Freeze seed, generator revisions/constants, finalized town/site inputs,
   required initial structure source manifests, patch/source digests, and one
   save-v2 snapshot.
2. Build a private native backend candidate through the retained load
   transaction. Pending work retains its owner and remains cancellable and
   drainable.
3. Pin patch-aware effective pages and compile replacement terrain artifacts.
4. Install/prepare replacement physical artifacts through the N5 physical
   owner while the old playable authority remains active.
5. Wait for physics acknowledgement and reject stale source, owner, epoch, or
   affected-set receipts.
6. In one Main-owned commit, switch the query facade, physical owner/readiness,
   save export owner/revision, and source epoch.
7. Only after that receipt may scene structures publish and gameplay leave the
   loading state.

For later streamed regions, repeat the boundary per complete affected page set:
stage a complete region replacement and all replacement collision artifacts,
then activate one source epoch for the whole affected set. Do not mutate the
active patch registry and wait for collision afterward.

Rollback rules:

- Before activation, cancel and drain the private patch/source/artifact
  candidate; the old authority remains untouched.
- Any missing, stale, rejected, or incomplete source/mesh/collision/physics
  receipt aborts the whole switch.
- After activation, rollback may reinstall only the complete predecessor
  source/query/physical bundle under a new owner epoch and actor-safe physical
  replacement. Never roll back queries alone while retaining new collision, or
  vice versa.
- Generated patches are not save deltas, so rollback never writes them into
  `terrainVolume`.

This matches the migration handoff's requirement to keep source, compiled,
installed, and usable states distinct; see
[`CODEX_NATIVE_WORLD_BACKEND_MIGRATION_HANDOFF_2026-09-17.md`](../../CODEX_NATIVE_WORLD_BACKEND_MIGRATION_HANDOFF_2026-09-17.md#44-source-compiled-installed-and-usable-are-different-states).
