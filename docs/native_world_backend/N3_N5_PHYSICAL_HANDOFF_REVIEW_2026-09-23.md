# N3/N5 production physical handoff review

Status: independent source audit at `4dd26ef`; **no production cutover or Gate 5 acceptance**.

## Acceptance assertions for the handoff

1. **Complete resident set.** For a pinned seed/source epoch and native revision, enumerate every demanded collision tile, including the player/NPC swept foreground, required startup/town closure, vertical range, and intersecting declared blockers. Gameplay readiness is true only if every member has an exact installed, physics-acknowledged receipt for that identity. Demand pending, native encode completion, inserted data, mesh-entered, a representative ray, or a ready aggregate count cannot substitute. Eviction, edit, actor relocation, source reset, and cancellation revoke the affected receipt before movement is admitted. Evidence must name required keys and missing dependencies. This is the N5 contract in the [migration handoff](../../CODEX_NATIVE_WORLD_BACKEND_MIGRATION_HANDOFF_2026-09-17.md); current `NativeTerrainRuntimeOwner.snapshot()` exposes a publisher snapshot but no such resident physical set (`scripts/terrain/NativeTerrainRuntimeOwner.gd`).

2. **Per-edit windows and safe replacement.** `NativeTerrainEditRepublicationPlan` already derives sorted affected mesh blocks and bounded subwindows from committed cells. The production owner must bind each subwindow to the exact source epoch/revision, prepared artifact, owner generation, and installed physics receipt; accept the edit barrier only when the union covers the entire planned set once. Hold movement through affected windows until then. A stale result or rejected install retains the last valid collider and retries current demand; rollback after shape mutation requires renewed physics proof, including the old geometry. Test adjacent/seam edits, repeated same-block edits, rapid reversal, unload/revisit, cancellation and forced acknowledgement failure. Current `inspect_edit_release_candidate()` deliberately returns `production_physical_owner_unbound` after checking only a caller-supplied receipt dictionary (`scripts/terrain/NativeTerrainRuntimeOwner.gd`); the planner's `publication_barrier_status()` is structural validation, not engine proof (`scripts/terrain/NativeTerrainEditRepublicationPlan.gd`).

3. **Actor clearance across physics frames.** A replacement must complete a bounded census of all relevant moving bodies, then prove each current shape and forecast motion clear of the exact replacement bounds before disabling old shapes and again during acknowledgement. Player, NPC, hostile and moving static placement/motion paths must share the admission barrier; an unregistered or newly spawned actor fails closed. Release requires the new exact physical receipt. Preinstall rejection may abandon admission only while old colliders remain live; after mutation, rollback needs a fresh old-geometry acknowledgement. `NativeCollisionAdmissionBarrier` and `NativeTerrainCollisionOwner` implement these local checks, but no production owner currently binds them to all resident tiles (`scripts/terrain/NativeCollisionAdmissionBarrier.gd`, `scripts/terrain/NativeTerrainCollisionOwner.gd`). The fixture must exercise actual `CharacterBody3D` motion and physics frames, not a direct helper result.

4. **Startup and Continue.** Menu New Game and v2 Continue must activate the same native source owner, keep loading visible while source/terrain/structure/navigation physical closure is pending, and fail explicitly on unavailable native binding or stale save/source identity. `startup_loading_completed` must follow complete current collision installation and actor registration; source bytes or a successful save import are insufficient. Verify cold and warm processes with a copied real v2 save, edited terrain, cancellation during conversion/preparation/installation, and source identity after reload. Existing startup calls `wait_for_initial_region_physical_readiness()` through `WorldStreamingCoordinator`; its terrain domain currently inherits Voxel Tools collision receipts (`scripts/MainCore.gd`, `scripts/world/WorldStreamingCoordinator.gd`, `scripts/terrain/VoxelTerrainRuntime.gd`).

5. **One terrain collision authority.** At cutover, production `VoxelTerrain.generate_collisions` and every viewer's `requires_collisions` must be false; the native owner installs the sole terrain physics shapes. Render meshing may consume native bytes but may not gate physical readiness or leave hidden Voxel Tools colliders. Require a headed scene assertion over collision layers/bodies before and after movement, edit and reset, plus a source audit for old readiness/probe callers. Today `VoxelTerrainRuntime` sets `generate_collisions = true` and collision-requiring viewers, while `NativeTerrainBlockPublisher` explicitly treats VoxelTerrain as temporary collision owner (`scripts/terrain/VoxelTerrainRuntime.gd`, `scripts/terrain/NativeTerrainBlockPublisher.gd`).

## Gaps to close before a live claim

- `NativeTerrainRuntimeOwner` is marked inert and its edit barrier has no production physical owner. Its publisher produces manual Voxel data and legacy generation-specific ray receipts; these do not establish the final source-revision-complete native collider set.
- `NativeTerrainCollisionOwner.replace()` locally validates an identity and artifact, but `_current()` compares a supplied result and authority dictionary. The runtime orchestrator must also recheck the live backend revision/epoch and demand membership before install and after each asynchronous physics frame, including retirement. A content-equivalent artifact from a replacement owner is not installation ownership.
- The collision owner accepts a bounded shape batch; production needs explicit spatial partitioning and local retained old/new representations so one edit does not replace an unrelated whole-world shape set. Measure construction, upload, physics sync and retirement separately.
- An artifact key alone is not geometry provenance: the owner must fetch the current source-owned triangle row (or verify its content digest) and reject changed vertices, bounds, probes, coordinate frame or block identity even when the caller repeats a valid key. An adversarial same-key/different-geometry fixture must fail before physics mutation. The N3 producer's synchronous mesher/build and vertex-copy portion also needs per-stage Main-frame timing before it can join responsive loading.
- The actor barrier's root must cover every gameplay-moving physics owner. Its local census is only sufficient if spawning, NPC/player/hostile motion, placement and independent physics callbacks all obey the same barrier during the replacement interval.
- Existing broad viewer collision and `published_gameplay_chunks` readiness must be retired or atomically translated at cutover. Keeping both and choosing whichever says ready would violate the single physical authority and leave the startup/Continue gate ambiguous.

No new contract is claimed here: the source-linked production binding and source-revision-complete resident set do not yet exist. Focused service/fixture contracts can verify local mechanics, but a headed normal startup, edit and movement fixture is required once the binding lands.
